# Suggested Scrum Sprint Plan

This is a plan, not a record of completed work. Set sprint dates and team member assignments based on your college schedule.

## Sprint 1 — Requirements, architecture and core setup

**Sprint goal:** A testable initial project with a clear scope, database schema, and working authentication.

- Write the project problem statement, scope and acceptance criteria
- Set up the Jira project, Scrum board and backlog
- Draft UI wireframes, architecture and entity relationship diagram
- Implement database tables and seed data
- Implement admin login and logout

**Definition of done:** Design artifacts reviewed; app runs locally and a test user can sign in.

## Sprint 2 — Inventory management features

**Sprint goal:** Staff can track products and perform stock operations.

- Add product and list products
- Edit and archive products
- Search and filter by category
- Stock-in and stock-out operations
- Transaction records and low-stock alerts
- Dashboard KPI cards and categories

**Definition of done:** New products persist across restart, stock quantities update correctly and invalid stock-out requests are rejected.

## Sprint 3 — Reporting, testing and handover

**Sprint goal:** Deliver a usable, tested prototype and evidence for final submission.

- Stock movement history
- CSV export report
- Test cases and bug fixing
- Review database integrity and invalid data handling
- Source code commit history and README
- Presentation materials and product demonstration

**Definition of done:** Critical manual tests pass, basic automated tests pass, report can be downloaded and known limitations are documented.

## Suggested roles (edit to fit your team)

- Scrum Master — coordinates the Jira board and sprint reviews
- Product Owner — prioritizes features and defines acceptance criteria
- Developer — frontend and backend changes
- QA / Documentation — testing, screenshots and report writing

For small teams, people may cover more than one role.
